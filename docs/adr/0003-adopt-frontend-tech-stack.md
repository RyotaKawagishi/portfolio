# ADR-0003: フロントエンド技術スタックに TypeScript、React、Vite、Tailwind CSS、Framer Motion を採用する

Date: 2026-06-02
Status: Accepted

## Context

このリポジトリでは、就活用ポートフォリオサイトを作成し、インターネット上に公開する。

このサイトはポートフォリオとして公開する静的サイトであり、今後、動的な機能を追加することは現時点では考慮しない。

また、この制作では完成物を公開するだけでなく、フロントエンドの学習も目的に含める。これまでRailsを使ったフルスタック開発とJavaScriptの経験が中心だったため、今回はTypeScript、React、モダンなスタイリング手法、Reactと相性のよいアニメーション実装を学ぶ。

## Decision

フロントエンド技術スタックとして、以下を採用する。

- 言語: TypeScript
- UIライブラリ: React
- 開発・ビルドツール: Vite
- スタイリング: Tailwind CSS
- アニメーション: Framer Motion

Next.jsやAstroは採用しない。

SassやGSAPも今回の初期実装では採用しない。

## Reasons

TypeScriptは、現代的なフロントエンド開発で広く使われており、就活用ポートフォリオとして説明しやすい。型があることで、コンポーネントのpropsやデータ構造の意図をコード上で示しやすく、実装中のミスにも気づきやすい。

React + Viteは、Reactの学習に集中しやすい構成である。Next.jsのような高機能フレームワークに浅い理解で乗るよりも、必要に応じてルーティングなどを自分で追加しながら理解する学習メリットを重視する。また、今後RailsバックエンドのフロントとしてReactを使う場合にも、この経験を活かしやすい。

Tailwind CSSは、Rails開発でSassを触った経験があるため、今回は未経験のスタイリング手法を学ぶ目的で採用する。ユーティリティクラスで素早くUIを組めるため、短期間でのポートフォリオ制作とも相性がよい。

Framer Motionは、Reactコンポーネントと相性がよく、Reactらしい書き方でアニメーションを実装できる。今回は高度なタイムライン制御や複雑なスクロール演出よりも、Reactの学習と基本的なUIアニメーションの実装を優先するため、GSAPではなくFramer Motionを採用する。

## Consequences

TypeScript、React、Viteを中心に学習できるため、フロントエンドの基礎理解を深めやすい。

React + ViteはNext.jsよりも軽量な構成であり、今回の静的ポートフォリオサイトには十分である。

一方で、Next.jsが標準で持つルーティング、画像最適化、メタ情報管理などは利用しない。必要な機能は、React側で個別に追加・設計する必要がある。

Tailwind CSSを採用することで短期間でUIを組みやすくなるが、クラス名が長くなりやすいため、コンポーネント分割や共通化を意識する必要がある。

Framer Motionを採用することでReactと相性のよい基本的なアニメーションは実装しやすくなる。一方で、複雑なスクロール演出や細かいタイムライン制御が必要になった場合は、GSAPなどの追加採用を再検討する。
