# ADR-0002: AI作業メモと正式ドキュメントを分離する

Date: 2026-06-01
Status: Accepted

## Context

このリポジトリでは、ポートフォリオサイトの制作過程で、AIとのやり取りを前提にした調査メモ、設計メモ、下書き、検討ログが発生する。

これらのメモには、未整理の情報、公開前の検討内容、最終成果物には含めない作業ログが含まれる可能性がある。

一方で、READMEやADRのように、公開してよい正式なドキュメントも必要になる。

作業メモと正式ドキュメントを同じ場所で管理すると、公開すべき情報と非公開の作業情報の境界が曖昧になる。

## Decision

AIとの作業中に発生するメモと、公開してよい正式ドキュメントを別ディレクトリで管理する。

- `ai-docs/`: AIとの作業メモ、調査、設計案、下書き、検討ログを置く
- `docs/`: 公開してよい正式ドキュメントを置く

`ai-docs/` はローカル作業領域として扱い、GitHubには公開しない。

公開してよい内容に整理できたものだけを `docs/` や `README.md` に移す。

重要な意思決定は、必要に応じてADRとして `docs/adr/` に記録する。

APIキー、トークン、パスワードなどの秘密情報や個人情報は、`ai-docs/` にも `docs/` にも置かない。

## Consequences

作業中の未整理な情報と、公開可能な正式ドキュメントの境界が明確になる。

公開前に内容を整理する流れを作れるため、誤って作業メモを正式ドキュメントとして扱うリスクを下げられる。

一方で、重要な内容を `ai-docs/` に置いたままにすると、正式なドキュメントへ反映されない可能性がある。そのため、残す価値がある決定や知見は `docs/` に移す必要がある。
