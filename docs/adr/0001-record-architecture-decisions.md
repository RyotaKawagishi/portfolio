# ADR-0001: アーキテクチャ上の意思決定を記録する

Date: 2026-06-01
Status: Accepted

## Context

このリポジトリでは、ポートフォリオサイトの制作にあたり、技術スタック、ページ構成、デザイン方針、デプロイ先などの意思決定が発生する。

これらの決定理由を残さない場合、後から「なぜその選択をしたのか」を確認しづらくなる。

## Decision

重要な技術的・設計的な意思決定はADRとして記録する。

ADRは `docs/adr/` 配下に配置し、ファイル名は4桁の連番と短いslugで表す。

```text
docs/adr/
  0001-record-architecture-decisions.md
  0002-example-decision.md
```

各ADRには、少なくとも以下を記載する。

- タイトル
- 日付
- ステータス
- 背景
- 決定内容
- 影響

ステータスは主に以下を使う。

- `Proposed`: 提案中
- `Accepted`: 採用済み
- `Superseded`: 別のADRに置き換え済み

## Consequences

意思決定の背景と理由を追跡しやすくなる。

一方で、すべての細かい判断までADR化すると運用負荷が高くなるため、後から参照する価値がある決定に絞って記録する。
